# Feature Specification: 微信小程序编译跑通 + 平台差异盘点

**Feature Branch**: `009-weapp-build-bootstrap`

**Created**: 2026-05-21

**Status**: Draft

**Input**: User description: "7.1 移植微信小程序的第一个 spec：让现有 Taro 代码能编译成微信小程序、在微信开发者工具里打开，并系统盘点平台差异，为后续地图适配/信源外链 spec 铺路。AppID: wxb4776856c0d56676。"

## Clarifications

### Session 2026-05-21

- Q: spec-009 的「跑到首页」算不算「连通后端 API」？ → A: 只要页面框架非白屏即算过。「小程序 ↔ 后端 API 网络层」（微信不允许调 localhost/IP、需 HTTPS 备案域名、小程序网络请求与浏览器 fetch 不同）作为一个差异项记入清单，留独立后续 spec 解决，不在 spec-009 范围。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Taro 代码编译成微信小程序产物（Priority: P1）

开发者希望现有的 Taro H5 项目能**编译出微信小程序产物**——跑一条构建命令，生成微信小程序能识别的代码包，不再只有 H5 一个目标。

**Why this priority**：P1，这是 7.1「移植小程序」整条线的地基。编译不通，后面地图适配、信源外链方案全都无从谈起——它们都建立在「有一个能跑的小程序产物」之上。

**Independent Test**：在 frontend 目录跑微信小程序构建命令，`dist/weapp`（或对应产物目录）成功生成，无致命编译错误。

**Acceptance Scenarios**:

1. **Given** 现有 Taro 项目（含 H5 配置），**When** 跑微信小程序构建命令，**Then** 产物目录生成、构建进程以成功状态结束、无致命（中断构建的）错误
2. **Given** 构建过程中某些 H5 专属代码（如高德 JS API）不兼容小程序，**When** 构建，**Then** 这类问题以警告/占位形式处理，不阻断整体产物生成（具体修复留给后续 spec）

---

### User Story 2 - 小程序能在微信开发者工具里启动到首页（Priority: P1）

开发者希望把编译产物导入微信开发者工具后，**小程序能启动、渲染出首页框架**——哪怕地图区域是空白或报错占位，至少整体骨架（搜索框、列表、导航栏）立得起来。

**Why this priority**：P1，「能编译」和「能在小程序运行时跑起来」是两回事。编译产物可能因为运行时 API 缺失直接白屏。这一步验证骨架真的活着，是后续逐项修复的前提。

**Independent Test**：用 AppID `wxb4776856c0d56676` 把产物导入微信开发者工具，小程序启动，首页非白屏——能看到页面框架元素。

**Acceptance Scenarios**:

1. **Given** 微信小程序产物 + AppID 已配置，**When** 微信开发者工具导入并编译预览，**Then** 小程序启动到首页、可见页面框架（搜索框/列表区/底部栏等非地图元素正常）
2. **Given** 地图组件在小程序运行时报错，**When** 首页加载，**Then** 地图区域显示占位/空白但**不导致整页白屏崩溃**（错误被隔离）

---

### User Story 3 - 产出平台差异清单，为后续 spec 铺路（Priority: P1）

开发者希望这一轮结束时，有一份**系统的「H5 ↔ 小程序 平台差异清单」**——把所有不兼容点列清楚、标严重度、建议归属哪个后续 spec，这样地图适配、信源外链等后续工作有明确的输入，不用边做边发现。

**Why this priority**：P1，这份清单是本 spec 的核心交付物之一。7.1 后续被切成多个 spec（地图、信源外链…），它们的范围划分直接依赖这份差异清单。没有它，后续 spec 无从规划。

**Independent Test**：检查 `docs/mvp-backlog/小程序平台差异清单.md` 存在，内含分类的不兼容点 + 每项严重度 + 建议归属 spec。

**Acceptance Scenarios**:

1. **Given** 编译 + 运行验证完成，**When** 查看差异清单文档，**Then** 文档分类列出所有发现的 H5↔小程序 不兼容点（地图 / 外链 web-view / 浏览器专属 API / 定位 / 其它），每项含：现象、严重度、建议归属的后续 spec
2. **Given** 差异清单完成，**When** 规划 spec-010（地图适配）等，**Then** 能直接从清单里圈定范围，无需重新摸排

---

### Edge Cases

- Taro 配置缺微信小程序段（`mini`/`weapp`）：补全配置，记录补了什么
- 某些 npm 依赖只支持 H5（如浏览器专属库）：构建报错时归入差异清单，不在本 spec 强行替换
- H5 端因本 spec 的配置改动而回归：本 spec 明确要求 H5 不能坏——配置改动须 H5/小程序双目标兼容
- 微信开发者工具未安装：本 spec 的运行验证（US2）需要它；属开发者本地环境前置
- 小程序包体积超限（微信 2MB 主包限制）：若触发，记入差异清单，分包优化留后续

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 frontend 项目补全微信小程序所需的项目配置（含 AppID `wxb4776856c0d56676`），使微信开发者工具能识别该项目
- **FR-002**: 系统 MUST 让微信小程序构建命令能成功执行并生成产物目录，无致命（中断构建）错误
- **FR-003**: 系统 MUST 确保构建产物在微信开发者工具中能启动到首页，首页非白屏（页面框架元素可见）；「首页能否拉到后端数据」**不在** spec-009 验收范围——页面框架立起来即算过
- **FR-004**: 系统 MUST 隔离地图等已知不兼容组件的运行时错误，使其不导致整页崩溃白屏（占位/空白可接受）
- **FR-005**: 系统 MUST 产出 `docs/mvp-backlog/小程序平台差异清单.md`，分类列出所有 H5↔小程序 不兼容点，每项标注现象、严重度、建议归属的后续 spec；清单 MUST 包含「小程序 ↔ 后端 API 网络层」一项（微信禁调 localhost/IP、需 HTTPS 备案域名、网络请求 API 与浏览器 fetch 不同），归属独立后续 spec
- **FR-006**: 系统 MUST 保证 H5 端不回归——本 spec 的所有配置/代码改动须 H5 与小程序双目标兼容；`build:h5` 仍正常、现有 H5 功能与测试不受影响
- **FR-007**: 系统 MUST NOT 在本 spec 内修复地图、信源外链 web-view 等平台差异（仅盘点、留后续 spec）
- **FR-008**: 系统 MUST NOT 改动任何后端代码或业务功能逻辑（本 spec 纯前端构建配置 + 盘点）

### Key Entities

- **平台差异清单（文档产物）**：每条记录含——不兼容点名称、所属类别（地图/外链/浏览器 API/定位/其它）、现象描述、严重度（阻断首页 / 功能缺失 / 体验降级）、建议归属的后续 spec
- **微信小程序项目配置**：含 AppID、项目名、编译设置等，使微信开发者工具能打开项目

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 微信小程序构建命令一条命令跑完、产物生成，开发者无需手动改产物即可导入开发者工具
- **SC-002**: 小程序在微信开发者工具里启动后，首页可见页面框架元素（非白屏）—— 人工核验
- **SC-003**: 平台差异清单覆盖所有当前能发现的不兼容点；后续 spec（地图适配等）能 100% 从清单圈定范围，无遗漏摸排
- **SC-004**: H5 端零回归——`build:h5` 成功、现有 88 条 pytest 与 H5 手动冒烟不受影响
- **SC-005**: 本 spec 完成后，7.1 剩余工作（地图 / 信源外链 / 导航 / 标注）每一块都能对应到差异清单里的具体条目

## Assumptions

- 产品前端是 Taro 4 + React 18，已具备 `build:weapp` 构建脚本，编译多端是 Taro 原生能力
- 微信小程序 AppID `wxb4776856c0d56676` 已注册（用户提供）
- 微信开发者工具由开发者本地安装（US2 的运行验证需要它；本 spec 不含其安装）
- 本 spec 是 7.1 的第一步，定位为「骨架立起来 + 摸清差异」，不追求小程序功能完整
- 后续 7.1 工作拆分为独立 spec：地图适配（IMapAdapter）、信源外链替代方案、导航跳转、AI 内容标注、**小程序↔后端 API 网络层**——均以本 spec 的差异清单为输入
- 小程序上线 / 审核 / ICP 备案不在本 spec，属后续部署阶段
