# Feature Specification: 后端 API 网络层适配微信小程序（代码侧）

**Feature Branch**: `011-weapp-api-network`

**Created**: 2026-05-21

**Status**: Draft

**Input**: User description: "后端 API 网络层适配微信小程序（R4，仅代码侧）。当前前端 API base URL 走环境变量 TARO_APP_API_BASE 但 fallback 硬编码 localhost；微信小程序禁止 localhost/IP、必须 HTTPS 域名。本 spec 让代码具备『连生产域名』能力，可在 H5 + 微信开发者工具验证，零回归。流式搜索 fetch ReadableStream 小程序不支持，需降级。不含买服务器/域名/ICP 备案/HTTPS 证书/微信后台配置等真实世界任务。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 小程序连的是可配置域名而非 localhost（Priority: P1）

开发者希望：构建小程序时，前端请求后端的地址来自一处可配置的来源，而不是写死的 `localhost`/`127.0.0.1`。这样未来拿到生产域名后，只改配置即可让小程序连上后端，无需翻代码。微信小程序硬性禁止请求 `localhost`/IP，写死 localhost 等于小程序永远拿不到数据。

**Why this priority**：P1，这是「小程序能连后端」的根。只要还有一处写死 localhost，小程序端列表/搜索就永远空白。这是 R4 代码侧的核心目标。

**Independent Test**：把生产域名变量设为一个测试域名，构建小程序，在微信开发者工具的 Network 面板看到 API 请求指向该域名而非 localhost；不设该变量时本地开发仍连本地后端。

**Acceptance Scenarios**:

1. **Given** 未配置生产域名变量，**When** 跑本地开发构建，**Then** 前端 API 请求指向本地后端地址，本地开发体验不变
2. **Given** 配置了生产域名变量，**When** 跑生产构建并在微信开发者工具运行，**Then** API 请求指向所配域名，Network 面板中不出现 `localhost`/`127.0.0.1`
3. **Given** 代码库全文检索，**When** 查找 API 地址相关写死值，**Then** 不存在「无法通过配置覆盖」的硬编码后端地址

---

### User Story 2 - AI 搜索在小程序端能返回结果（降级路径）（Priority: P1）

用户在小程序里做 AI 搜索，希望能正常拿到搜索结果。当前 H5 端 AI 搜索是「逐字蹦出来」的流式效果，底层用浏览器原生 `fetch` 流式读取——微信小程序不支持这个能力。若不处理，小程序端 AI 搜索会直接报错或卡死。本故事让小程序自动改走「一次性返回完整结果」的非流式路径，对用户而言搜索照常可用，只是少了逐字动效。

**Why this priority**：P1，AI 搜索是产品核心功能。在小程序端报错 = 核心功能不可用。降级后「能用但无动效」远好于「直接坏」。

**Independent Test**：微信开发者工具里触发一次 AI 搜索，控制台无流式 API 相关报错，搜索结果能完整返回并展示。

**Acceptance Scenarios**:

1. **Given** 用户在小程序端发起 AI 搜索，**When** 请求执行，**Then** 走非流式路径一次性返回完整结果，结果正常展示
2. **Given** 小程序端 AI 搜索进行中，**When** 查看控制台，**Then** 无 `fetch`/`ReadableStream`/流式相关报错
3. **Given** 同一份调用 AI 搜索的页面代码，**When** 分别在 H5 与小程序运行，**Then** 调用方写法一致、无需为两端写两套调用——平台差异由网络层内部消化

---

### User Story 3 - H5 端零回归（Priority: P1）

开发者希望本 spec 所有改动**不破坏 H5 端**：H5 的 API 调用地址、AI 搜索的流式「逐字」效果、其它所有接口行为，与改动前完全一致。

**Why this priority**：P1，H5 是已上线可用形态。为小程序改网络层时把 H5 改坏，是「修一端坏一端」的负和操作。零回归是硬约束。

**Independent Test**：`build:h5` 成功；H5 端 AI 搜索仍是逐字流式效果；H5 端各接口（点位列表、统一搜索、反馈提交等）功能与改动前一致。

**Acceptance Scenarios**:

1. **Given** 本 spec 完成，**When** 跑 H5 构建并使用 AI 搜索，**Then** 仍是逐字流式效果，与改动前一致
2. **Given** H5 端各业务接口，**When** 改动后使用，**Then** 行为与改动前一致，无报错、无功能缺失

---

### User Story 4 - 后端允许生产域名跨域访问（Priority: P2）

运维/开发者希望：后端的跨域访问白名单（CORS）能通过配置加入生产前端域名，这样 H5 站点部署到生产域名后浏览器不会因跨域被拦。当前白名单只有本地地址。

**Why this priority**：P2。比 US1/US2 次要——微信小程序本身不走浏览器 CORS 校验，所以它不阻塞「小程序连后端」；CORS 只影响 H5 生产站点。但属于 R4「网络层适配」同一范畴，顺带一并做完。

**Independent Test**：通过配置项加入一个测试域名，后端启动后该域名出现在允许的跨域来源中；不配置时仍保留本地地址。

**Acceptance Scenarios**:

1. **Given** 通过配置项指定了生产前端域名，**When** 后端启动，**Then** 该域名被纳入跨域允许来源
2. **Given** 未指定生产域名配置，**When** 后端启动，**Then** 仍允许本地开发地址，本地联调不受影响

---

### Edge Cases

- 生产构建时未配置生产域名变量：构建不应静默产出一个连 localhost 的「假生产包」——应能让开发者明确知道（构建提示/失败/或留有据可查的占位默认值）
- 平台判断：网络层须能可靠区分「当前运行在 H5 还是小程序」，判断失败时应安全降级（默认走兼容性更强的非流式路径而非崩溃）
- 微信开发者工具默认校验「合法域名」白名单：开发阶段验证依赖在工具里勾选「不校验合法域名」——这是工具配置项，不在代码范围，须在文档/假设中写明
- AI 搜索降级路径较慢（无逐字反馈，用户等待期间无进度感）：小程序端须有常规加载态，避免用户以为卡死
- CORS 配置项为空或格式错误：后端应回退到本地默认白名单，不应启动失败

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 让前端请求后端的地址来自单一可配置来源，区分本地开发与生产两种环境——本地默认连本地后端，生产由配置指定域名
- **FR-002**: 系统 MUST NOT 在任何「无法通过配置覆盖」的位置写死后端地址（含前端源码、前端构建配置、容器编排配置）
- **FR-003**: 生产构建在未配置生产域名时 MUST NOT 静默产出一个指向 `localhost` 的生产包——须以构建提示、构建失败或明确的占位默认值之一让开发者可察觉
- **FR-004**: 系统 MUST 在小程序端把 AI 搜索从流式路径自动切换为非流式（一次性返回）路径，使 AI 搜索在小程序端可正常返回结果
- **FR-005**: 系统 MUST 保持 H5 端 AI 搜索的流式「逐字」效果不变
- **FR-006**: AI 搜索的流式/非流式差异 MUST 由网络层内部消化——调用页面用同一套调用方式，无需按平台分支
- **FR-007**: 系统 MUST 能可靠判断当前运行平台（H5 / 小程序）以决定走流式还是降级路径；判断不确定时 MUST 安全地走非流式路径
- **FR-008**: 后端跨域允许来源 MUST 支持通过配置项加入生产前端域名，且未配置时回退到本地默认白名单、不影响本地联调
- **FR-009**: 系统 MUST 保证 H5 端零回归——API 调用地址、AI 搜索流式效果、各业务接口（点位列表、统一搜索、反馈提交等）行为与改动前一致；`build:h5` 正常
- **FR-010**: 配置样板文件 MUST 补充生产相关配置项的样例与说明注释，让后续部署者知道要配哪些项
- **FR-011**: 系统 MUST NOT 涉及购买云服务器/域名、ICP 备案、申请 HTTPS 证书、微信小程序后台配置服务器域名、nginx 部署等真实世界任务——这些由用户在代码之外处理

### Key Entities

- **API 地址配置**：前端连后端的唯一地址来源；有「本地开发」与「生产」两种取值，由环境/构建配置决定当前用哪个
- **平台标识**：标记当前代码运行在 H5 还是微信小程序，网络层据此决定流式或降级路径
- **AI 搜索请求**：有「流式」与「非流式」两种实现路径，对调用方表现为同一接口
- **跨域允许来源白名单**：后端记录的允许跨域访问的前端来源集合，可经配置扩展

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全代码库检索，写死且无法配置覆盖的后端地址数量为 0
- **SC-002**: 微信开发者工具运行小程序，Network 面板中 API 请求指向所配域名，`localhost`/`127.0.0.1` 出现次数为 0
- **SC-003**: 微信开发者工具触发 AI 搜索，结果完整返回，控制台流式相关报错数为 0
- **SC-004**: H5 端 AI 搜索仍为逐字流式效果——人工核验与改动前一致
- **SC-005**: H5 端各业务接口功能与改动前一致——人工核验无回归；`build:h5` 成功
- **SC-006**: 通过配置项可成功把一个生产域名加入后端跨域白名单，未配置时本地联调不受影响
- **SC-007**: 生产构建未配置域名时，开发者能明确察觉（提示/失败/占位默认值之一），不会误把连 localhost 的包当生产包

## Assumptions

- spec-009/spec-010 已完成：小程序能编译、能在微信开发者工具启动并显示首页框架
- 本 spec 处理差异清单的 R4（后端 API 网络层），仅代码侧
- 真实世界任务（云服务器、域名、ICP 备案、HTTPS 证书、微信后台配服务器域名、nginx）不在本 spec，由用户并行处理；本 spec 完成后代码已「就绪」，拿到域名即可配置接入
- 开发阶段在微信开发者工具中验证网络请求，依赖工具内勾选「不校验合法域名」选项——此为工具配置，非代码改动
- 前端是 Taro 4 + React 18，平台差异通过 Taro 的运行环境标识处理；后端是 FastAPI
- 「生产域名」在本 spec 中以占位/测试值代替——真实域名待用户备案后填入
- 验证靠：`build:weapp` + 微信开发者工具人工核验（API 指向、AI 搜索降级）/ `build:h5` + H5 人工核验零回归；后端 CORS 改动可加 1 条 pytest 覆盖
- AI 搜索降级后小程序端无逐字动效属预期行为，不视为缺陷
