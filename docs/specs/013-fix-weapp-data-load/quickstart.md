# Quickstart 验证清单：修复微信小程序端点位数据加载不出来

**Feature**: 013-fix-weapp-data-load | **Date**: 2026-05-22

实现完成后按本清单逐项核验。前端无单测设施 → 全靠双端构建 + 微信开发者工具人工核验。

---

## 准备

- worktree 根目录 `.env` 已就位（缺则从主仓库 `cp`）
- 本地后端起：`backend` 目录 venv 跑 `uvicorn app.main:app --reload`（curl `127.0.0.1:8000/api/v1/health` 应秒回）
- Docker Postgres 在跑（点位数据源）

---

## 第 1 节 · 小程序：默认中心也能加载点位（US1 + US2 核心）

```bash
cd frontend && npm run build:weapp
```

微信开发者工具打开 `frontend/dist/`，勾「不校验合法域名」：

- [ ] 小程序首页加载后，**地图上出现点位 marker**（不再空白）
- [ ] 底部列表面板有点位条目（不再「来源点位 0」一片空）
- [ ] 「调试器 → Network」面板里有对 `/api/v1/places` 的真实请求（请求数 ≥ 1）
- [ ] 若弹出定位授权请求 → **点「拒绝」**，确认拒绝后地图/列表仍有点位（杭州默认中心兜底）

---

## 第 2 节 · 小程序：定位授权能跑通（US3）

- [ ] 小程序首次需要定位时，**弹出微信位置授权请求**（而非无弹窗直接失败）
- [ ] 在授权弹窗点「允许」→ 地图能居中到（微信开发者工具模拟的）位置，并据此加载点位

> 微信开发者工具可在「调试器 → Sensor / 模拟」里设置模拟定位。

---

## 第 3 节 · 小程序：启动无报错（US4）

- [ ] 「调试器 → Console」**无未被捕获的 `Error: timeout`** 红错
- [ ] 若仍有 → 记录栈信息（这是 research D4 的假设待证伪点，需进一步查）

---

## 第 4 节 · H5 零回归（US5）

```bash
cd frontend && npm run build:h5
```

浏览器用 `http://localhost:10086` 打开（用 localhost，不用 LAN IP）：

- [ ] H5 定位成功时——点位加载、地图、列表 与改动前一致
- [ ] H5 定位失败/拒绝时——也能用杭州默认中心显示点位（改动前是空白，这属修复）
- [ ] `build:h5` 构建成功

---

## 第 5 节 · 边界

- [ ] 默认中心（杭州）附近确有点位（已知 DB 有数据），故应能看到 marker；若恰好筛选后为空，显示「该区域暂无点位」而非报错
- [ ] 点位请求失败（如后端没起）时，有用户可见的失败提示，不是静默空白

---

## 验收口径

- 第 1、4 节全勾 = 核心修复达成（小程序能加载点位 + H5 零回归）
- 第 3 节 `Error: timeout`：若消失则 D4 假设成立；若仍在需继续查，不阻塞核心修复的判定
- 小程序部分依赖微信开发者工具人工核验，无自动化替代
