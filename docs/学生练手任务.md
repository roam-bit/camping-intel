# 学生练手任务

> 6 个任务，难度递增。每个都注明**改哪个文件**、**怎么验证做对了**。
> 先按 [学生快速启动.md](学生快速启动.md) 把项目跑起来。

**通用纪律**（这是本项目自己的开发铁律，也建议你养成）：
> 改完顺手加 1 条测试。修 bug 的话，注明"防止这个 bug 再来"。

## ⭐ 任务 1：加一个你自己的示例查询 + 对应数据

**难度**：入门 · **预计**：30 分钟 · **成就感**：第一次打通「前端 → 后端 → 数据库 → 地图」全链路

现在首屏有 3 个示例查询芯片（杭州周边免费露营地 / 莫干山附近营地 / 千岛湖驻车点）。加第 4 个，比如你老家附近的。

**改两处**：
1. `frontend/src/components/EmptyHero.tsx` — 找到 `EXAMPLE_QUERIES` 数组，加一条
2. `backend/scripts/seed_demo_spots.py` — 找到 `CLUSTERS`，照葫芦画瓢加一簇点位

⚠️ **关键点**：种子数据的 `summary` 字段里**必须包含地名关键词**，否则后端的关键词检索匹配不上，你点了芯片会走 AI 兜底（慢 30 秒）而不是秒回。

**怎么验证**：重跑 `backend/.venv/bin/python backend/scripts/seed_demo_spots.py`，刷新页面，点你的新芯片——应该 1 秒内出你编的点位。

## ⭐⭐ 任务 3：让"没有 Key 的人"也能看到示例查询

**难度**：中等 · **预计**：1 小时 · **这是一个真实存在的体验缺陷，还没人修**

现在的问题：`frontend/src/pages/index/index.tsx` 里，引导卡的显示条件是

```js
{!hasSearched && !searching && !mapError && !heroDismissed && ( <EmptyHero .../> )}
```

注意那个 **`!mapError`** ——只要地图出错（比如没配高德 Key），引导卡就整个消失。结果是：**没 Key 的新用户既看不到地图，也看不到"你可以搜什么"的提示**，只能对着搜索框发呆。

**你的任务**：让引导卡在"地图不可用但产品可用"时依然显示。

**难点提示**（这才是这个任务的价值）：
- `EmptyHero` 是**绝对定位在地图中央**的，直接放进列表视图会错位——你得处理布局
- 改完要确认 `frontend/e2e/test_h5_ui.py` 里那两条 `test_hero_visible_*` 测试**仍然通过**（它们守着一个真实修过的 bug：引导卡曾经被排到视口外，用户从没见过它）

**怎么验证**：把 `.env` 里的高德 Key 改成 `your-amap-web-key`，重启，看首屏有没有示例查询。

## ⭐⭐⭐ 任务 4：给搜索结果加"搜索中心"徽章

**难度**：中等 · **预计**：1 小时 · **特点**：后端能力已经做好了，只是前端没用

后端每次搜索都会返回它识别出的地名，字段是 `source_breakdown.detected_place`。比如你搜「莫干山附近营地」，它返回 `detected_place: "莫干山"`。

现在前端只用这个字段做地图平移，**没有把它显示出来**。用户不知道系统到底把搜索中心定在哪了——搜偏了也不知道为什么。

**你的任务**：在搜索结果区显示一个徽章，比如「📍 搜索中心：莫干山」。

**改**：`frontend/src/pages/index/index.tsx` + 对应 CSS

**怎么验证**：搜「莫干山附近营地」和「千岛湖驻车点」，看徽章文字跟着变。

## ⭐⭐⭐ 任务 5：把你自己搜到的点位，变成随项目分发的数据

**难度**：中等 · **预计**：1.5 小时 · **价值**：理解什么叫"数据资产"

这个项目里有 561 个点位是**随代码一起分发**的（`backend/seed_data/places_seed.json`）——所以你 clone 下来打开就有内容，而不是一个空库。这批数据是作者一次次跑 AI 搜索沉淀出来的。

**你的任务**：给它添砖加瓦。

1. 配好 `ARK_API_KEY`（见 [学生快速启动.md](学生快速启动.md) 进阶部分）
2. 在产品里搜几个**你自己家乡/常去区域**的露营点，让 AI 真的联网抓一批新数据
3. 用导出脚本把库里的数据重新导出：
   ```bash
   docker compose exec api python scripts/export_seed_data.py
   ```
4. 看 `git diff` —— 你会看到 `places_seed.json` 里多出了你搜到的点位
5. 验证别人能用：`docker compose down -v && docker compose up`，你的点位应该自动回来

**要动脑的地方**（这才是任务价值所在）：
- 导出脚本只导 `status IN ('active','pending_review')` 的点位。**为什么不全导？**（提示：看脚本里的注释，和库里 `hidden` 状态有多少条）
- 导入脚本用的是 `ON CONFLICT (id) DO NOTHING`。**如果改成 DO UPDATE 会发生什么？**对多人协作有什么影响？
- 如果两个同学各自搜了一批数据，怎么合并？JSON 文件会冲突吗？

**收获**：AI 产品的"数据飞轮"不是抽象概念——用得越多，资产越厚，这就是它的具体形态。

## ⭐⭐⭐⭐ 任务 6：走一遍完整的规格驱动开发流程

**难度**：进阶 · **预计**：3-4 小时 · **这是本项目最有教学价值的部分**

项目 `docs/specs/` 目录下有 16 个功能规格，每个都是「先写规格 → 再写计划 → 再拆任务 → 最后写代码」的完整留痕。你可以先读一个感受一下，推荐 `docs/specs/017-amap-geo-fallback/spec.md`——它记录了一个真实事故：

> 用户搜「莫干山」，系统查不到，去调地图 API，结果返回了**福建一个同名地点**，搜索中心飞到 500 公里外，等了 34 秒返回 0 个结果。

看它怎么把一句用户抱怨，变成 3 个带优先级的用户故事 + 可验收的场景 + 性能护栏。

**你的任务**：用同样的流程做一个新功能——**搜索历史**（把用户最近 3 次搜索存在浏览器本地，显示在首屏）。

**流程**（项目里装了对应的工具）：
```
/speckit-specify  → 写规格（要什么、边界在哪、怎么算做完）
/speckit-clarify  → 让 AI 反问你没说清的地方
/speckit-plan     → 生成实现计划
/speckit-tasks    → 拆成具体任务
/speckit-implement→ 按任务写代码
```

**彩蛋**：这个功能在项目早期被讨论过，当时因为优先级不够被放弃了。你等于把一个落选提案捡起来做成了。

**怎么验证**：搜三次不同的词，刷新页面，历史还在。

## 做完之后

如果你改出了有意思的东西，最有价值的不是代码本身，而是**你能讲清楚**：
- 你改之前，它为什么是那样的？（读懂原作者的约束）
- 你改之后，什么变好了？有没有变坏的地方？
- 你怎么证明它真的好了？（截图 / 测试 / 数据）

这三个问题，就是产品经理和工程师每天在回答的问题。
