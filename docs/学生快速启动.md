# 学生快速启动

> **只需要装一样东西，敲一条命令。**
> Node、Python、数据库、建表、数据 —— 全都在容器里，你一个都不用装。

---

## 一、装 Docker Desktop（唯一的前置条件）

| 系统 | 下载地址 |
|---|---|
| Windows | <https://www.docker.com/products/docker-desktop/> |
| macOS | <https://www.docker.com/products/docker-desktop/>（注意选 Apple 芯片 / Intel 芯片对应版本） |

装完**打开它**，等左下角鲸鱼图标不再转圈（变成绿色/静止）就算好了。

> ⚠️ **Windows 用户**：安装时如果提示需要 WSL2，跟着弹窗点"安装"即可，Docker 会自己处理。
> ⚠️ 装完记得给 Docker 分配至少 **4GB 内存**（Settings → Resources → Memory），前端编译吃内存。

---

## 二、跑起来（一条命令）

在项目文件夹里打开终端，敲：

```bash
docker compose up
```

**Windows 用 PowerShell 或 CMD 都行，命令一模一样**（不需要 Git Bash、不需要 WSL 终端）。

### 第一次跑会发生什么

| 阶段 | 你会看到 | 大概多久 |
|---|---|---|
| 拉基础镜像 | `Pulling postgres/redis/python/node...` | 2-5 分钟 |
| 装后端依赖 | `pip install ...` | 1-3 分钟 |
| 装前端依赖 | `npm install ...`（1100+ 个包，最慢的一步） | 3-8 分钟 |
| 建表 + 导入数据 | `Running upgrade → 0001_init_baseline...` | 10 秒 |
| 前端编译 | `编译成功` | 1-2 分钟 |

**首次总计 8-20 分钟**（看网速）。第二次之后 30 秒内起来。

### 看到这些就是成功了

```
✓ 种子数据就绪：新增 549 个点位…；当前库内共 549 个点位
重置完成：删旧 0 个 → 插入 18 个演示点位
INFO:     Uvicorn running on http://0.0.0.0:8000
✅  编译成功
```

浏览器打开 **<http://localhost:10086>**，你会看到地图上密密麻麻的露营点。

## 四、出问题了怎么办（按顺序排查）

### 🔧 第 1 招：先看是不是这几个常见情况

| 你看到 | 原因 | 怎么办 |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop 没打开 | 打开它，等鲸鱼图标不转了再重试 |
| `port is already allocated` / `address already in use` | 端口被别的程序占了 | 见下方【端口冲突】 |
| `npm ERR! network` / `pip ... timeout` | 网络拉包失败 | 见下方【网络慢/拉不动】 |
| 容器都起来了，但页面打不开 | 前端还在编译 | 等 `✅ 编译成功` 出现再刷新 |
| 页面打开了但一个点位都没有 | 后端还没起完 | 等 10 秒刷新；仍然没有看【页面空白】 |
| 构建到一半卡死不动 | Docker 内存不够 | Settings → Resources → Memory 调到 4GB 以上 |

### 🔧 第 2 招：端口冲突

本项目要用 4 个端口：**10086**（页面）、**8000**（后端）、**5432**（数据库）、**6379**（缓存）。

先看是谁占了：
```bash
# macOS / Linux
lsof -i:10086

# Windows
netstat -ano | findstr :10086
```

**最简单的解法是关掉那个程序。** 如果关不掉，在项目根目录建一个 `docker-compose.override.yml`，把端口改掉：

```yaml
services:
  frontend:
    ports: ["20086:10086"]
  api:
    ports: ["18000:8000"]
    environment:
      TARO_APP_API_BASE: http://localhost:18000
  postgres:
    ports: ["15432:5432"]
  redis:
    ports: ["16379:6379"]
```

然后重新 `docker compose up`，页面地址变成 <http://localhost:20086>。

> Docker 会自动读取 `docker-compose.override.yml` 并覆盖主配置，不用改原文件。

### 🔧 第 3 招：网络慢 / 拉不动

项目**默认已经用了国内镜像源**（清华 pypi + npmmirror），一般不用管。

如果基础镜像（postgres/node/python）拉不下来，给 Docker 配个加速器：
Docker Desktop → Settings → Docker Engine，在 JSON 里加：

```json
{
  "registry-mirrors": ["https://docker.m.daocloud.io"]
}
```

点 Apply & Restart，再重试。

反过来，如果你在**海外或公司网络**，国内源反而慢，改用官方源：
```bash
docker compose build --build-arg PIP_INDEX_URL=https://pypi.org/simple --build-arg NPM_REGISTRY=https://registry.npmjs.org
```

### 🔧 第 4 招：页面空白 / 没有点位

按顺序做：

```bash
# 1. 看四个容器是不是都在跑
docker compose ps

# 2. 看后端说了什么
docker compose logs api | tail -30

# 3. 直接问后端要数据（应该返回一堆 JSON）
curl http://localhost:8000/api/v1/places?lat=30.27&lon=120.15&radius_km=80&limit=5
```

如果第 3 步没数据，手动补一次：
```bash
docker compose exec api python scripts/load_seed_data.py
```

### 🔧 终极大招：推倒重来

**这一招能解决 90% 的疑难杂症**，代价是重新下载依赖（8-20 分钟）：

```bash
docker compose down -v      # 停掉所有容器 + 清空数据库
docker compose up --build   # 重新构建、重新来一遍
```

> `-v` 会**清空数据库**。你自己搜出来的新点位会没了，随仓库分发的 561 个点位会自动重新导入。

### 🆘 还是不行

把这三样发给老师/助教：
1. `docker compose ps` 的输出
2. `docker compose logs api | tail -50` 的输出
3. 你的系统（Windows / macOS）和 Docker Desktop 版本

## 五、常用命令备忘

```bash
docker compose up          # 启动（前台，能看日志，Ctrl+C 停）
docker compose up -d       # 启动（后台）
docker compose down        # 停止（数据保留）
docker compose down -v     # 停止 + 清空数据库
docker compose logs -f api # 实时看后端日志
docker compose restart api # 只重启后端
docker compose ps          # 看容器状态
```

**改了代码要重启吗？** 不用。前后端都开了热更新，改完存盘就生效。
只有改了 `requirements.txt` 或 `package.json`（增删依赖）才需要 `docker compose up --build`。

把项目根目录的 `.env`（第一次跑会自动生成）里的占位符换成真 Key：

改完 `docker compose restart` 一下。

> ⚠️ **别把填了真 Key 的 `.env` 提交到 Git**。`.gitignore` 已经挡了，别绕过去。

也可以，但要自己装 Node 18+ 和 **Python 3.9–3.12（不能是 3.13+）**：

```bash

```

Windows 需要 Git Bash 或 WSL。这条路的坑比 Docker 多，**除非你想练环境配置，否则建议走 Docker**。
